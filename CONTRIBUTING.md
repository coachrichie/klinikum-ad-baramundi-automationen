# Mitwirken

Änderungen über einen separaten Branch und Pull Request einreichen. Für neue Logik zuerst einen fehlgeschlagenen Pester-Test dokumentieren, danach implementieren und die vollständige Suite sowie die PowerShell-Parserprüfung ausführen.

Nur synthetische Beispieldaten verwenden. Sicherheitsgrenzen, Berechtigungen, Datenschutz und Einschränkungen nachvollziehbar dokumentieren. Keine Systemänderungen in Audit-Pakete aufnehmen. PRs werden vor einer Übernahme manuell geprüft; kein Auto-Merge.
